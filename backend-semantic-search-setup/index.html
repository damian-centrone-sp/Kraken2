Guía de setup y pruebas del backend de búsqueda semántica

1. Levantar el backend

Desde hoopis-backend: 

npm run docker:up:build

La OPENAI_API_KEY debe estar configurada en:

  • .env.local, para transcribir los videos.
  • microservices/ai-gateway/.env.local, para embeddings y búsqueda.

URLs:

  • Nest Swagger: http://localhost:3000/docs
  • FastAPI Swagger: http://localhost:8100/docs
  • AI Gateway health: http://localhost:8100/health

2. Subir los cursos

Se pueden subir desde Content Factory o desde Nest Swagger. Desde Swagger:

  1. Registrarse o iniciar sesión y cargar el accessToken en Authorize.
  2. Crear el curso con POST /api/v1/content-factory/editor-documents.
  3. Guardar document.id y document.contentItemId.
  4. Subir el video con POST /api/v1/content-factory/editor-documents/{id}/video-upload.
  5. Iniciar la transcripción con POST /api/v1/content-factory/editor-documents/{id}/pipeline/transcription-requests.
  6. Esperar a que termine y verificar que se hayan generado las oraciones de la transcripción.

Los embeddings se indexan automáticamente después de una transcripción exitosa.

Importante:
• document.id se usa para Content Factory.
• document.contentItemId se usa para buscar.

3. Probar la búsqueda (local)

Abrir http://localhost:8100/docs y ejecutar POST /v1/learner-platform/semantic-search: 

{
  "query": "¿Qué debería hacer si recibo un correo que parece una estafa?",
  "allowedContentItemIds": [
    "<contentItemId-curso-seguridad>",
    "<contentItemId-curso-finanzas>",
    "<contentItemId-curso-liderazgo>"
  ],
  "limit": 10
}

Este endpoint local no requiere bearer token. También se puede probar con cURL: 

curl -X POST \
  'http://localhost:8100/v1/learner-platform/semantic-search' \
  -H 'Content-Type: application/json' \
  -d '{
    "query": "¿Qué debería hacer si recibo un correo que parece una estafa?",
    "allowedContentItemIds": [
      "<contentItemId-1>",
      "<contentItemId-2>"
    ],
    "limit": 10
  }'

4. Prueba en staging

Subir los cursos. Abrir Content Factory en https://dq2cthshjb7ho.cloudfront.net/content-factory, subir los cursos y esperar a que termine la transcripción. Los cursos también deben estar disponibles en el catálogo de Learner Platform para el mismo tenant usado por QA: la búsqueda filtra cualquier curso que no sea visible para ese tenant.

Ejecutar la búsqueda. En staging no hay Swagger público; la prueba debe hacerse con Postman o cURL: 

POST https://dq2cthshjb7ho.cloudfront.net/api/v1/learner-view/search
Authorization: Bearer <staging-learner-token>
Content-Type: application/json

{
  "query": "¿Qué debería hacer si recibo un correo que parece una estafa?",
  "limit": 20
}

Debe usarse un token de learner del mismo tenant que los cursos. Se puede copiar desde una request autenticada en la pestaña Network del navegador. No compartir el token por Slack o Jira.

Ejemplo con cURL:

curl -X POST \
  'https://dq2cthshjb7ho.cloudfront.net/api/v1/learner-view/search' \
  -H 'Authorization: Bearer <staging-learner-token>' \
  -H 'Content-Type: application/json' \
  -d '{
    "query": "¿Qué debería hacer si recibo un correo que parece una estafa?",
    "limit": 20
  }'

Qué validar

  • Palabras exactas: buscar una frase que aparezca solamente en un curso.
  • Similitud semántica: buscar la misma idea usando palabras diferentes.
  • Ranking: el curso más relacionado debería aparecer primero.
  • Fragmento: matched_chunk.text debería mostrar la parte relevante de la transcripción.
  • Timestamps: start_ms y end_ms deberían coincidir aproximadamente con el fragmento.
  • Límite: con "limit": 1 no debería volver más de un resultado.
  • Tenant: nunca deberían aparecer cursos pertenecientes solamente a otro tenant.

relevance y matched_chunk.score son valores de ranking, no porcentajes de confianza. El primer resultado puede tener 1.0 porque los puntajes están normalizados.

Un 401 en staging normalmente significa que el token falta, venció o no contiene el contexto de learner y tenant. Si un curso transcripto no aparece, primero hay que confirmar que esté disponible en el catálogo del mismo tenant.
